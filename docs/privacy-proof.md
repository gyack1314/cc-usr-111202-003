# 分层计数发布的隐私论证与账本一致性

本文给出 `research_data` 分层加噪发布的机制级论证。隐私结论来自 Laplace 机制的
定义性质与后处理不变性，不依赖任何有限次模拟；测试只用于核对实现与数学结论一致，
不充当证明。

## 1. 数据模型与相邻关系

- 每个受试者由稳定 `subject_id` 标识，可携带多条事件。
- 公开分类树 `tree` 固定、有根、等深、叶类全部公开；事件只能引用叶节点。
- 贡献选择是公开的确定性规则：同一 `subject_id` 的事件按
  `(event_day, event_id)` 升序，每人只保留第一条，其余事件不贡献任何计数。
  排序键与类别、事件结果无关，选择函数本身不查看也不依赖任何隐私输出。
- **相邻数据集**定义为加入或删除一个人的全部记录。经贡献选择后，相邻数据集在
  每个树层上的计数向量只在一个节点上相差 1（新增/移除的那个人唯一入选事件的
  祖先链每层各一个节点），因此**每个树层向量的 L1 敏感度均为 1**。
  `tests/test_sensitivity.py` 在小树上对加入和删除两个方向核对了这一点。

## 2. Laplace 机制与每层预算

对深度 `d` 的每个节点 `v`，独立发布

```
y_v = count_v + Lap(b_d),   b_d = 1 / epsilon_d
```

- `epsilon_d` 事先登记为正有理数（分数字符串），不接受事后调整。
- Laplace 机制对 L1 敏感度为 1 的向量查询满足 `epsilon_d`-差分隐私：
  密度比按 L1 距离被 `exp(epsilon_d)` 界住，这是 Laplace 机制的标准定义性质。
- 同层各节点噪声相互独立；**真计数为零的叶同样加噪**，发布覆盖树的全部公开
  节点，不暴露“哪些类别出现过”这一信息。
- 随机源：
  - `publication`（默认）：`secrets` 支持的操作系统 CSPRNG，无种子、不可复现；
  - `demonstration`：仅用于明确标记的演示材料，固定种子、回执带
    `publishable=false` 与禁止发布声明，不产生可对外使用的隐私凭证。

### 2.1 总预算（顺序组合）

各层机制作用于同一数据集且独立加噪，按差分隐私的顺序组合定理，整次发布满足

```
epsilon_total = sum_d epsilon_d
```

账本以 `Fraction` 精确分数累计该值，比较余额时不使用二进制浮点，避免
`1/3+1/3+1/3` 一类舍入导致的超支判断错误。

## 3. 一致化是后处理，不增加隐私损失

各层独立加噪通常不满足父子相加。一致化只读取已发布的加噪向量 `y` 与公开的
每层方差 `var_v = 2 / epsilon_d^2`，求解

```
min_x  sum_v (x_v - y_v)^2 / var_v
s.t.   x_v = 子节点和（内部节点）,  x_leaf >= 0
```

- 用叶向量 `w >= 0` 参数化 `x = A w`，等价于带权非负最小二乘，由
  Lawson–Hanson 主动集法求解（`consistency.py`），输出连续实数计数、
  可重算目标值、KKT 最优性残差与父子约束残差。
- “把负值截零再按比例摊平”是另一种启发式，**不是**该二次规划的最优解；
  测试在构造案例上验证了最优解目标严格小于该启发式。
- 求解过程不读取真实计数、不接触随机源，属于对机制输出的纯函数变换。
  按后处理不变性，一致化不增加任何隐私损失。
- **不强制根等于真实总数**：那会构成一个新的无噪声查询并泄漏信息；根节点只
  参与同一个带权最小二乘。

## 4. 预算账本的一致性论证

账本是单个 SQLite 文件，金额为精确分数字符串，`release_id` 是
`(privacy_scope, release_id)` 幂等键。

### 4.1 两个同时提交请求的额度竞争

每个请求在一个 `BEGIN IMMEDIATE` 事务内完成“余额校验 → 建单 → 扣款 → 提交”。
该语句立即申请写锁，并发事务在锁上排队，因此临界区天然串行化：任何时刻只有
一个事务能读到并修改 `scopes.spent`。每笔事务在提交前重新计算
`spent + charge <= budget`，后来者看到的是前者已提交的余额，所以无论多少请求
并发，已扣款总额都不会超过 scope 预算；超额请求拒绝并回滚，不留下部分写入。
`tests/test_ledger.py::test_concurrent_requests_never_overspend` 用 5 个线程
在同一屏障后竞争只能容纳 2 单的预算，核对恰好 2 单成功、3 单 `BudgetExceeded`、
账本支出精确等于预算。同 ID 并发请求则被唯一主键与指纹检查收敛为一次扣款、
其余全部返回同一回执。

### 4.2 故障恢复

- **建单/抽样失败**：发生在事务提交前，异常触发 `ROLLBACK`，scope 行与支出
  都不保留，同一 `release_id` 可干净重试（测试验证回滚后账本查无该 scope）。
- **提交后投递失败**：扣款与回执已在提交点持久化，对外投递（写文件、发消息
  等）在事务之外；投递失败不回滚预算，调用方用同一 `release_id` 重试，账本
  命中既有记录并返回**字节级同一份**回执，不重新抽样、不二次扣款。
- **进程崩溃**：SQLite 事务原子性保证崩溃只可能发生在提交前（无任何痕迹）或
  提交后（完整记录可见），不存在半笔预算；WAL 模式保证崩溃后可重新打开。
- 因此“发布失败也保留已消耗额度”的语义与可恢复性同时成立。

### 4.3 重复请求与参数冲突

- 同 `(scope, release_id)` 且请求指纹相同：返回存储的同一回执，
  `receipt_hash` 不变，支出只计一次。指纹覆盖树、事件内容、每层 epsilon、
  scope 预算、数据版本、模式与求解器参数，经规范 JSON 后取 SHA-256。
- 同 ID 但指纹不同（内容或机制参数变化）：抛 `IdempotencyConflict`，拒绝且
  不扣款；同一 scope 登记不同总额度抛 `ScopeBudgetConflict`。
- `dataset_version` 与文件名都不重置预算：预算只按固定人群的
  `privacy_scope` 累计，换文件名重复发布同一批资料会作为新 release 正常累计
  消耗，无法通过改名规避预算。

### 4.4 账本与对外回执的边界

- 指纹与完整回执存于本地账本；对外回执只含公开树、加噪计数、一致化计数、
  机制参数、方差与预算快照。
- 真实 `subject_id`、真实计数、随机种子（含演示种子）均不出现在回执中；
  `check_receipt_hygiene` 与专门测试强制这一点。
- 回执自带 `receipt_hash`（不含哈希字段本身的规范 JSON 的 SHA-256），把
  可见数字、噪声参数与预算快照绑定为一份不可混淆、可独立重算的发布凭证。

## 5. 不做的事与边界

- 不发布任何未加噪计数；`inspect` 子命令的原始摘要仅供本地维护，明确不是
  发布结果。
- 不用模拟频率估计 epsilon 或“验证隐私”；随机性测试只核对确定性（演示种子
  可复现）、独立性外观与输出卫生。
- 本工具不处理 epsilon 之外的会计维度（如 delta）：机制是纯 ε-DP，无高斯噪声、
  无近似差分隐私参数。
